# Лабораторная работа №6. Разработка серверной части приложения

## Цель работы

Изучить основы разработки серверной части веб-приложений на PHP, создать структуру проекта, реализовать маршрутизацию HTTP-запросов и разработать контроллеры для обработки запросов пользователей.

## Описание структуры проекта

Проект построен по паттерну MVC и имеет следующую структуру:

```
backend/
├── public/ # единственная папка, доступная из интернета
│ ├── index.php # единая точка входа
│ └── css/style.css # оформление
│
├── app/
│ ├── autoload.php # автозагрузка классов
│ ├── helpers.php 
│ │
│ ├── Core/
│ │ └── Router.php # маршрутизатор
│ │
│ ├── Controllers/
│ │ ├── HomeController.php # главная страница
│ │ ├── OrderController.php # заказы
│ │ └── DishController.php # блюда
│ │
│ ├── Models/
│ │ ├── OrderRepository.php # работа с storage/orders.json
│ │ └── DishRepository.php # работа с storage/dishes.json
│ │
│ └── Views/
│ ├── layout/ # шапка
│ ├── errors/ # 404 и 500
│ ├── home.php # главная страница
│ ├── orders/ # index, show, create
│ └── dishes/ # index, show
│
├── routes/
│ └── web.php # таблица маршрутов
│
├── config/
│ └── app.php # настройки приложения
│
└── storage/
├── orders.json # данные заказов
└── dishes.json # данные блюд
```

### Назначение каталогов

| Каталог | Назначение |
| --- | --- |
| `public/` | Точка входа и статические файлы: всё, что открывается по прямому адресу |
| `app/Controllers/` | Контроллеры: обработка запросов |
| `app/Models/` | Модели: данные и работа с ними |
| `app/Views/` | Шаблоны страниц |
| `app/Core/` | Ядро приложения: маршрутизатор |
| `routes/` | Таблица маршрутов |
| `config/` | Настройки приложения |
| `storage/` | Файлы с данными |

Все запросы направляются в `public/index.php` — единую точку входа. Здесь определяются пути к каталогам, подключаются автозагрузка и вспомогательные функции, создаётся маршрутизатор, подключается таблица маршрутов, и вызывается `dispatch()` с методом и адресом запроса. Наружу открыта только папка `public/` — остальные каталоги недоступны по прямому адресу, что защищает модели, настройки и данные.

## Описание механизма маршрутизации

Маршрут — это правило «на такой запрос отвечает такой код». Маршрут состоит из метода (`GET` или `POST` и др.), шаблона адреса и обработчика (класс контроллера и его метод). Все маршруты собраны в `routes/web.php`:

```php
$router->get('/', [HomeController::class, 'index']);
$router->get('/orders', [OrderController::class, 'index']);
$router->get('/orders/create', [OrderController::class, 'create']);
$router->post('/orders', [OrderController::class, 'store']);
$router->get('/orders/{id}', [OrderController::class, 'show']);
$router->get('/dishes', [DishController::class, 'index']);
$router->get('/dishes/{id}', [DishController::class, 'show']);
```

## Описание реализованных контроллеров

### HomeController
index() — главная страница. Считает общее число заказов, разбивку по статусам (new, cooking, ready, paid), количество блюд в меню. Передаёт данные в шаблон home.php.

### OrderController
index() — список заказов. Поддерживает фильтр ?status= (например, /orders?status=cooking). Фильтрация выполняется в контроллере через array_filter. Передаёт в шаблон список заказов и текущий фильтр.

show($id) — просмотр одного заказа. Если заказа с таким id нет — вызывает notFound() (страница 404 с кодом ответа 404). Передаёт в шаблон заказ и связанное блюдо.

create() — форма создания заказа. Передаёт список блюд для выпадающего списка.

store() — обработка отправленной формы. Читает данные из $_POST, проверяет их на сервере:

client_name — не короче 3 символов,

dish_id — должен существовать в dishes.json,

amount — число больше нуля.

При ошибках возвращает код 422 и перерисовывает форму с сообщениями и сохранёнными значениями.

### DishController
index() — список всех блюд.

show($id) — просмотр блюда. Если блюда нет — notFound(). Дополнительно показывает список заказов, связанных с этим блюдом (через метод byDish() модели).

## Вывод
В ходе работы изучены принципы построения серверной части веб-приложения на PHP. Реализован механизм маршрутизации, обрабатывающий HTTP-запросы по методу и адресу, с поддержкой параметров в URL и корректной обработкой ошибок. Разработаны три контроллера для основных сценариев (главная, список, просмотр, создание), с разделением ответственности по паттерну MVC: модели отвечают за данные, представления — за отображение, контроллеры связывают их. Перенос на предметную область «Система заказов ресторана» показал, что архитектура MVC позволяет менять предметную область, не затрагивая инфраструктурный код. Маршрутизатор, автозагрузка и вспомогательные функции не менялись — потребовалось только переименовать сущности и адаптировать шаблоны.
